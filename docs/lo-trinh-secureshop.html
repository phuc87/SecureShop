Lộ trình xây dựng SecureShop

Website bán thiết bị an ninh có trợ lý tư vấn AI, có chat và gọi video giữa khách hàng và admin trên 2 laptop khác nhau. Kế hoạch gồm 8 giai đoạn trong khoảng 12 tuần, xếp theo thứ tự phụ thuộc: phần nào là nền cho phần sau thì làm trước.

Mỗi việc có ô đánh dấu để bạn theo dõi tiến độ. Trạng thái được lưu trong trình duyệt của bạn.

Frontend React + Vite Backend Node.js + Express CSDL MongoDB (Mongoose) Realtime Socket.IO Video WebRTC AI LLM API qua backend Ảnh Cloudinary

Làm gì trước, làm gì sau

Thanh màu cam là phần rủi ro cao nhất (gọi video giữa 2 máy). Phần này được thử ngay từ tuần 1 bằng một bản demo nhỏ, để nếu mạng hoặc HTTPS có vấn đề thì bạn biết sớm.

Middleware phân quyền

const jwt = require('jsonwebtoken');

exports.requireAuth = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'Chưa đăng nhập' });
  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET); // { id, role }
    next();
  } catch {
    res.status(401).json({ message: 'Token không hợp lệ' });
  }
};

exports.requireRole = (role) => (req, res, next) =>
  req.user.role === role ? next() : res.status(403).json({ message: 'Không có quyền' });

Khung xử lý phía server

// server/src/socket/index.js
io.use((socket, next) => {
  try {
    socket.user = jwt.verify(socket.handshake.auth.token, process.env.JWT_SECRET);
    next();
  } catch { next(new Error('unauthorized')); }
});

io.on('connection', (socket) => {
  const { id, role } = socket.user;
  socket.join(`user:${id}`);
  if (role === 'admin') socket.join('admins');

  socket.on('chat:send', async (data, ack) => {
    const conv = await Conversation.findById(data.conversationId);
    if (!canAccess(conv, socket.user)) return ack?.({ error: 'forbidden' });

    const msg = await Message.create({ ...data, senderId: id, senderType: role });
    await conv.updateOne({ lastMessageAt: msg.createdAt });
    io.to(`user:${conv.customerId}`).to('admins').emit('chat:message', msg);
    ack?.({ ok: true, id: msg._id });
  });

  registerCallHandlers(io, socket); // giai đoạn 5
});

Xong khi

  • Laptop A (khách) và laptop B (admin) nhắn qua lại tức thời. Reload trang vẫn còn lịch sử.
  • Admin gửi thẻ sản phẩm, khách bấm vào mở đúng trang sản phẩm.

Bẫy hay gặp

  • Gọi socket.on trong useEffect mà không có hàm dọn (socket.off) làm tin nhắn hiện 2–3 lần.
  • Tạo kết nối socket mới mỗi lần render. Chỉ tạo 1 kết nối trong SocketContext.

5Gọi video WebRTC giữa 2 laptop

Tuần 7–8

Mục tiêu: khách và admin gọi video ngay trong khung chat, có bật/tắt camera và mic, chia sẻ màn hình, và lưu lịch sử cuộc gọi. Phần này đưa bản thử ở giai đoạn 0 vào ứng dụng thật.

Việc cần làm

Phần lõi WebRTC phía client

const ICE = { iceServers: [
  { urls: 'stun:stun.l.google.com:19302' },
  { urls: 'turn:a.relay.metered.ca:443', username: TURN_USER, credential: TURN_PASS },
]};

let pc, localStream, pendingIce = [];

async function setupPeer(peerId) {
  pc = new RTCPeerConnection(ICE);
  localStream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
  localStream.getTracks().forEach(t => pc.addTrack(t, localStream));
  localVideo.srcObject = localStream;

  pc.ontrack = (e) => { remoteVideo.srcObject = e.streams[0]; };
  pc.onicecandidate = (e) => e.candidate &&
    socket.emit('webrtc:ice-candidate', { to: peerId, candidate: e.candidate });
}

// Bên gọi (sau khi nhận call:accept)
async function startCall(peerId) {
  await setupPeer(peerId);
  const offer = await pc.createOffer();
  await pc.setLocalDescription(offer);
  socket.emit('webrtc:offer', { to: peerId, sdp: offer });
}

// Bên nhận
socket.on('webrtc:offer', async ({ from, sdp }) => {
  await setupPeer(from);
  await pc.setRemoteDescription(sdp);
  pendingIce.forEach(c => pc.addIceCandidate(c)); pendingIce = [];
  const answer = await pc.createAnswer();
  await pc.setLocalDescription(answer);
  socket.emit('webrtc:answer', { to: from, sdp: answer });
});

socket.on('webrtc:answer', ({ sdp }) => pc.setRemoteDescription(sdp));

socket.on('webrtc:ice-candidate', ({ candidate }) =>
  pc?.remoteDescription ? pc.addIceCandidate(candidate) : pendingIce.push(candidate));

// Chia sẻ màn hình
async function shareScreen() {
  const screen = await navigator.mediaDevices.getDisplayMedia({ video: true });
  const sender = pc.getSenders().find(s => s.track?.kind === 'video');
  sender.replaceTrack(screen.getVideoTracks()[0]);
  screen.getVideoTracks()[0].onended = () =>
    sender.replaceTrack(localStream.getVideoTracks()[0]);
}

Xong khi

  • Từ khung chat, admin bấm gọi và khách nhận được trên laptop kia, có hình và tiếng 2 chiều.
  • Admin chia sẻ màn hình trang thông số sản phẩm cho khách xem được.
  • Gọi được cả khi 2 máy khác mạng.

Bẫy hay gặp

  • ICE candidate đến trước setRemoteDescription thì bị lỗi. Cần cho vào hàng đợi như đoạn code trên.
  • React StrictMode chạy useEffect 2 lần nên tạo 2 RTCPeerConnection. Hãy giữ pc trong useRef.
  • Quên track.stop() khi kết thúc làm đèn camera vẫn sáng.
  • Thẻ <video> của mình thiếu muted nên bị hú (vọng tiếng).

6Trợ lý AI tư vấn

Tuần 8–10

Mục tiêu: AI hỏi nhu cầu và gợi ý đúng sản phẩm đang bán, kèm giá thật. Khi khách cần người thật, AI chuyển cho admin kèm bản tóm tắt.

Trạng thái hội thoại khi chuyển AI sang admin

Việc cần làm

Mẫu system prompt

Bạn là trợ lý tư vấn của SecureShop, cửa hàng thiết bị an ninh.
Quy tắc:
- Chỉ giới thiệu sản phẩm có trong DANH SÁCH SẢN PHẨM bên dưới. Không bịa tên, giá, thông số.
- Nếu chưa rõ nhu cầu, hỏi tối đa 2 câu: lắp ở đâu (nhà/shop/kho, trong nhà/ngoài trời),
  diện tích hoặc số vị trí cần quan sát, ngân sách.
- Gợi ý 1–3 sản phẩm, giải thích ngắn vì sao phù hợp.
- Nếu khách muốn gặp người thật, hỏi lắp đặt tận nơi, bảo hành, đổi trả, hoặc bạn không chắc
  câu trả lời → đặt handoff = true.
- Trả lời bằng tiếng Việt, thân thiện, ngắn gọn.

Chỉ trả về JSON đúng dạng:
{ "reply": "...", "productIds": ["..."], "handoff": false, "summary": "..." }

DANH SÁCH SẢN PHẨM:
{{products}}   ← backend chèn: id | tên | giá | thông số chính | tồn kho

Endpoint phía server

router.post('/ai/chat', aiLimiter, async (req, res) => {
  const { message, history = [] } = req.body;
  const products = await findRelevantProducts(message);   // lọc MongoDB
  const prompt = buildSystemPrompt(products);
  const raw = await callLLM(prompt, [...history.slice(-10), { role: 'user', content: message }]);

  let out;
  try { out = JSON.parse(raw); }
  catch { out = { reply: raw, productIds: [], handoff: false }; }

  const valid = products.filter(p => out.productIds?.includes(String(p._id)));
  res.json({ reply: out.reply, products: valid, handoff: !!out.handoff, summary: out.summary });
});

Xong khi

  • Hỏi "camera ngoài trời dưới 1 triệu" thì AI gợi ý đúng sản phẩm có trong DB, đúng giá.
  • Nói "cho tôi gặp nhân viên" thì admin trên laptop B nhận được thông báo kèm tóm tắt.

Bẫy hay gặp

  • Gọi LLM trực tiếp từ React làm lộ khóa API.
  • Đưa toàn bộ lịch sử chat vào prompt khiến tốn token và chậm.
  • Tin tuyệt đối vào productIds do AI trả. Luôn đối chiếu lại với DB.

7Dashboard, deploy, kiểm thử & báo cáo

Tuần 10–12

Mục tiêu: hoàn thiện trang quản trị, đưa hệ thống lên mạng có HTTPS, chuẩn bị kịch bản demo trên 2 laptop và viết báo cáo.

Việc cần làm

Kịch bản demo trên 2 laptop (khoảng 7 phút)

  1. Laptop A (khách): mở web, hỏi AI "Tôi cần camera cho shop quần áo khoảng 50m², ngân sách 2 triệu". AI hỏi thêm 1 câu rồi gợi ý 2 sản phẩm có thẻ.
  2. Laptop A: bấm "Gặp tư vấn viên".
  3. Laptop B (admin): nghe âm báo, thấy hội thoại mới kèm tóm tắt của AI rồi bấm Nhận.
  4. Laptop B: nhắn tin và gửi thẻ sản phẩm đầu ghi để đi kèm camera.
  5. Laptop B: bấm Gọi video. Laptop A nhận cuộc gọi, hai bên thấy nhau.
  6. Laptop B: chia sẻ màn hình bảng thông số để giải thích. Kết thúc cuộc gọi, tin "Cuộc gọi 2 phút" xuất hiện trong chat.
  7. Laptop A: bấm thẻ sản phẩm, thêm vào giỏ, đặt hàng COD.
  8. Laptop B: mở Dashboard thấy đơn mới, doanh thu tăng; xác nhận đơn và khách thấy trạng thái đổi.

Xong khi

  • Kịch bản chạy trơn tru 2 lần liên tiếp.
  • Có link HTTPS công khai hoặc ngrok dự phòng, và có video quay lại demo phòng khi mạng hôm bảo vệ có sự cố.

Bẫy hay gặp

  • Gói miễn phí của Render "ngủ" sau 15 phút không dùng, request đầu tiên mất khoảng 50 giây. Hãy mở trước khi demo.
  • WiFi trường có thể chặn kết nối P2P. Lúc này TURN qua cổng 443 là bắt buộc.

Thời lượng tính theo 1 người làm khoảng 15–20 giờ/tuần. Làm nhóm 2–3 người thì chia theo cột: một người phụ trách cửa hàng, một người phụ trách chat và video, một người phụ trách AI và dashboard. Nhóm có thể chạy song song từ tuần 3.
